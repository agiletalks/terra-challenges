以下是可以直接交給設計師的**逐頁簡報製作規格**。
定位是：**10 分鐘內帶完的雙語設計思考微體驗簡報**，對象為台灣與日本學生。

---

# 簡報整體規格

## 1. 簡報目的

這份簡報不是理論課，而是帶學生完成一個短活動：

> 從「我肚子餓」這個表面問題出發，讓學生體驗：
> **探索 → 定義 → 發展 → 交付**
> 以及設計思考中的**發散與收斂**。

---

## 2. 語言原則

採用：

> **英文為主視覺，繁中為輔助說明**

原因：現場有台灣與日本學生，英文作為共同語言最公平；繁中保留給台灣學生與講師現場帶場使用。

### 語言呈現方式

| 元素    | 語言                                                |
| ----- | ------------------------------------------------- |
| 頁面主標題 | 英文＋繁中                                             |
| 活動指令  | 英文大字                                              |
| 補充說明  | 繁中小字                                              |
| 4D 階段 | Discover 探索 / Define 定義 / Develop 發展 / Deliver 交付 |
| 講者備註  | 繁中即可                                              |

---

## 3. 視覺風格

建議風格：

> **清爽、現代、教育工作坊感，不要太商業簡報感**

### 視覺關鍵字

| 面向 | 要求                                             |
| -- | ---------------------------------------------- |
| 風格 | Clean / Workshop / Minimal / Friendly          |
| 色彩 | 白底或淡米色底，搭配 1–2 個主色                             |
| 字體 | 英文使用清楚的 Sans-serif；中文使用思源黑體、Noto Sans TC 或同級字體 |
| 圖示 | 使用簡單線性 icon，不要卡通過度                             |
| 版面 | 大標題、少文字、大留白                                    |
| 情緒 | 輕鬆、有互動感，但不要幼稚                                  |

### 建議色彩

可以用這組：

| 用途      | 色彩建議              |
| ------- | ----------------- |
| 背景      | #FAF7F0 或 #FFFFFF |
| 主色      | 深綠 #2F5D50        |
| 輔助色     | 暖橘 #F2A65A        |
| 強調色     | 深灰 #2B2B2B        |
| 提醒 / 反轉 | 紅棕 #B85C38        |

---

# 簡報頁數

共 **9 頁**。

| 頁數 | 功能          |
| -: | ----------- |
|  1 | 開場          |
|  2 | 出題：肚子餓      |
|  3 | 收集直覺方案      |
|  4 | 揭露限制，製造落差   |
|  5 | Discover 探索 |
|  6 | Define 定義   |
|  7 | Develop 發展  |
|  8 | Deliver 交付  |
|  9 | 發散收斂總結圖     |

---

# 逐頁製作規格

---

## Slide 1｜開場

### 頁面目的

建立活動氣氛，讓學生知道接下來不是聽講，而是要參與一個小體驗。

### 主標題

**Don’t Feed Me Too Fast**
**不要急著餵我**

### 副標

**A 10-minute Design Thinking activity**
10 分鐘設計思考體驗

### 視覺要求

* 可使用簡單食物 icon，例如飯糰、便當、香蕉、豆漿。
* 不要放真實食物照片，避免太像餐飲簡報。
* 畫面要輕鬆，但仍有設計感。
* 標題置中，大字。

### 動畫

* 標題淡入。
* 副標延遲 0.5 秒淡入。
* 食物 icon 可輕微浮現，不要太花。

### 倒數計時

不需要。

---

## Slide 2｜出題：我肚子餓

### 頁面目的

讓學生快速進入直覺解方模式，製造後面的落差。

### 主標題

**I’m Hungry.**
**我肚子餓。**

### 指令文字

**In 30 seconds, suggest one solution.**
請在 30 秒內想一個解決方案。

### 視覺要求

* 畫面中央放大「I’m Hungry.」
* 下方放 30 秒倒數計時器。
* 可放一個簡單胃部或空碗 icon。
* 畫面不要透露後面限制。

### 動畫

* 「I’m Hungry.」先出現。
* 指令文字接著出現。
* 倒數計時器最後出現並啟動。

### 倒數計時

需要。

| 項目   | 規格                            |
| ---- | ----------------------------- |
| 時長   | 30 秒                          |
| 呈現   | 大型圓形倒數或數字倒數                   |
| 位置   | 頁面下方中央                        |
| 結束提示 | 倒數到 0 時可出現 “Time’s up!” / 時間到 |
| 聲音   | 可有輕微提示音，但不要刺耳                 |

---

## Slide 3｜收集直覺方案

### 頁面目的

讓學生說出第一輪直覺方案，並讓這些方案可視化。

### 主標題

**Your First Ideas**
**你們的直覺方案**

### 主文字

**What would you do?**
你會怎麼做？

### 選項文字

可依序出現：

* Meal?
  便當？
* Bread?
  麵包？
* Drink?
  飲料？
* Delivery?
  外送？
* Convenience store?
  便利商店？

### 視覺要求

* 用卡片式版面呈現 5 個選項。
* 每張卡片可搭配簡單 icon。
* 卡片不要太像正確答案，只是呈現「直覺方案」。

### 動畫

* 標題先出現。
* 五張卡片依序出現。
* 每張卡片間隔約 0.2–0.3 秒。

### 倒數計時

不需要。

### 講者操作

這頁可停下來請 2–3 組回答。

---

## Slide 4｜揭露限制，製造落差

### 頁面目的

創造認知落差，讓學生發現：剛剛很多解方可能不適合。

### 主標題

**But…**
**但是……**

### 限制條件

請分四段依序出現：

1. **I’m vegetarian.**
   我吃素。
2. **I need to drive to Yilan.**
   我等一下要開車到宜蘭。
3. **The drive takes about 1.5 hours.**
   車程大約一個半小時。
4. **I can’t easily stop for the restroom.**
   中間不方便下車上廁所。

### 視覺要求

* 「But…」要大，形成轉折感。
* 四個限制可用垂直清單或四張限制卡。
* 每個限制搭配簡單 icon：

  * Vegetarian：葉子
  * Drive：車子
  * 1.5 hours：時鐘
  * Restroom：廁所符號加限制符號
* 視覺不要太搞笑，保持工作坊專業感。

### 動畫

* 先只出現 **But…**
* 講師停頓後，四個限制一條一條出現。
* 每條可用淡入或滑入。
* 最後可讓前一頁的方案淡淡變灰或打問號，表示「原解方不一定成立」。

### 倒數計時

不需要。

---

## Slide 5｜Discover 探索

### 頁面目的

正式進入 4D 的第一階段：探索。
讓學生知道現在任務不是給建議，而是問問題。

### 主標題

**Discover｜探索**

### 主指令

**Ask questions. Don’t give advice yet.**
先問問題，不急著給建議。

### 補充文字

**Find out my context, constraints, and real needs.**
問出我的狀態、限制、情境與真正需求。

### 可放小提示

四個問題方向：

* Current state
  現在狀態
* Constraints
  限制條件
* Context
  接下來情境
* Desired outcome
  想達成的效果

### 視覺要求

* 這頁開始要出現 4D 小導覽列，放在頁面上方或下方：
  Discover → Define → Develop → Deliver
* 在這頁高亮 Discover。
* 可使用「放大鏡」或「問號」icon。
* 版面要有探索、打開的感覺，例如左側有多個問題泡泡。

### 動畫

* 標題出現。
* 主指令出現。
* 四個問題方向依序出現。
* 倒數計時器出現並啟動。

### 倒數計時

需要。

| 項目   | 規格                                       |
| ---- | ---------------------------------------- |
| 時長   | 90 秒                                     |
| 呈現   | 大型倒數或進度條                                 |
| 位置   | 右上角或下方中央                                 |
| 結束提示 | “Stop asking. Let’s define.” / 停止提問，開始定義 |
| 注意   | 倒數不要佔太大版面，因為這頁還要看任務指令                    |

---

## Slide 6｜Define 定義

### 頁面目的

讓學生把表面問題重新定義成真正問題。

### 主標題

**Define｜定義**

### 主問題

**What is the real problem we are solving?**
我們真正要解決的是什麼問題？

### 對照文字

左側：

**Surface problem**
表面問題

> I’m hungry.
> 我肚子餓。

右側：

**Real problem**
真正問題

> How might we help a vegetarian person get just enough energy before a 1.5-hour drive, without feeling too full, thirsty, bloated, or needing the restroom?

中文小字：

> 如何在出發前，幫一位吃素、準備開車 1.5 小時且途中不方便上廁所的人，補充剛好的能量，又避免太飽、口渴、脹氣或想上廁所？

### 視覺要求

* 使用左右對照。
* 左邊可以比較小、灰色，表示原始表面問題。
* 右邊比較大、深色，表示重新定義後的問題。
* 可用箭頭從左指向右。
* 4D 導覽列高亮 Define。

### 動畫

* 左側 Surface problem 先出現。
* 箭頭出現。
* 右側 Real problem 出現。
* 右側文字可用醒目框線標示。

### 倒數計時

建議不需要。
這頁由講師帶學生口頭收斂。

---

## Slide 7｜Develop 發展

### 頁面目的

讓學生根據重新定義後的問題，提出新版方案。

### 主標題

**Develop｜發展**

### 主指令

**Create a better solution based on the real need.**
根據真正需求，提出一個新版解方。

### 補充提示

**Don’t just find food. Design for the situation.**
不要只找食物，要設計符合情境的補給方案。

### 可放評估條件

新版方案要考慮：

* Vegetarian
  吃素
* Fast
  快速取得
* Light
  不過飽
* Low restroom risk
  降低想上廁所風險
* Suitable for driving
  適合開車前

### 視覺要求

* 可使用發想卡片或便利貼風格。
* 4D 導覽列高亮 Develop。
* 可用「燈泡」icon。
* 版面要有發散感，可出現多張空白便利貼。

### 動畫

* 標題出現。
* 主指令出現。
* 五個評估條件依序出現。
* 倒數計時器出現並啟動。

### 倒數計時

需要。

| 項目   | 規格                        |
| ---- | ------------------------- |
| 時長   | 60 秒                      |
| 呈現   | 倒數數字或進度條                  |
| 位置   | 右上角或下方中央                  |
| 結束提示 | “Pick one idea.” / 選出一個方案 |

---

## Slide 8｜Deliver 交付

### 頁面目的

讓學生把解方拿來測試，體驗交付與回饋。

### 主標題

**Deliver｜交付**

### 主指令

**Test your idea. Would I really use it?**
把你的解方拿來測試：我真的會採用嗎？

### 評分規則

**I will score your idea from 1 to 5.**
我會給你的方案 1–5 分。

**5 = I would use it now.**
5 分 = 我現在真的會採用。

**If it’s below 5, ask: “What’s missing?”**
低於 5 分，請追問：「還差什麼？」

### 視覺要求

* 畫面可放一個簡單評分尺：1 2 3 4 5。
* 5 分要有明顯標示，但不要太像遊戲得分。
* 4D 導覽列高亮 Deliver。
* 可使用「測試」「回饋」「打勾」相關 icon。

### 動畫

* 標題出現。
* 主指令出現。
* 評分尺出現。
* 「低於 5 分請追問」最後出現，作為重點。
* 若有時間，可讓 1–5 分數由左至右依序出現。

### 倒數計時

可選。

建議如果現場時間緊，這頁放 **60 秒倒數**；如果你想彈性互動，可以不放。

| 項目   | 規格                              |
| ---- | ------------------------------- |
| 時長   | 60 秒，可選                         |
| 用途   | 控制測試與回饋時間                       |
| 位置   | 右上角                             |
| 結束提示 | “What did we learn?” / 我們學到了什麼？ |

---

## Slide 9｜發散與收斂總結圖

### 頁面目的

把前面的活動收斂成設計思考框架。
這是整份簡報最重要的概念圖。

### 主標題

**Diverge & Converge**
**發散與收斂**

### 副標

**Design Thinking is not about jumping to answers.**
設計思考不是急著給答案。

### 圖示內容

請設計一個簡化版雙鑽石圖，四階段依序為：

1. **Discover｜探索**
2. **Define｜定義**
3. **Develop｜發展**
4. **Deliver｜交付**

圖上文字：

| 階段          | 圖上小字                      |
| ----------- | ------------------------- |
| Discover 探索 | Explore the situation     |
| Define 定義   | Focus the real problem    |
| Develop 發展  | Create possible solutions |
| Deliver 交付  | Test and learn            |

中文小字可放在英文下方：

| 階段 | 中文小字 |
| -- | ---- |
| 探索 | 打開資訊 |
| 定義 | 聚焦問題 |
| 發展 | 打開解方 |
| 交付 | 測試學習 |

### 圖形要求

* 使用清楚的發散 / 收斂圖形。
* Discover 是發散。
* Define 是收斂。
* Develop 是發散。
* Deliver 是收斂。
* 可做成雙鑽石：

  * 第一個鑽石：Discover → Define
  * 第二個鑽石：Develop → Deliver
* 每一階段用不同深淺或輔助色區分，但保持整體一致。

### 底部總結句

**First understand the problem. Then design the solution.**
先理解問題，再設計解方。

或使用更有力的版本：

**Don’t answer too fast. Make sure you are solving the right problem.**
不要太快回答，先確認你解決的是對的問題。

### 視覺要求

* 這頁要最乾淨、最像結論頁。
* 圖示要大，文字要少。
* 不要放太多說明段落。
* 這頁會是學生最後拍照的頁面，請提高可讀性。

### 動畫

建議分四段出現：

1. Discover 探索出現。
2. Define 定義出現，形成第一個鑽石。
3. Develop 發展出現。
4. Deliver 交付出現，形成第二個鑽石。
5. 最後出現底部總結句。

### 倒數計時

不需要。

---

# 倒數計時器統一規格

簡報中建議有三個必要倒數、一個可選倒數。

|      頁數 | 用途             |   時間 | 必要性 |
| ------: | -------------- | ---: | --- |
| Slide 2 | 第一輪直覺解方        | 30 秒 | 必要  |
| Slide 5 | Discover 探索提問  | 90 秒 | 必要  |
| Slide 7 | Develop 發展新版方案 | 60 秒 | 必要  |
| Slide 8 | Deliver 交付測試   | 60 秒 | 可選  |

## 倒數計時器視覺規格

| 項目 | 要求                   |
| -- | -------------------- |
| 樣式 | 圓形倒數、數字倒數或底部進度條皆可    |
| 字體 | 大、清楚、遠距離可讀           |
| 色彩 | 與主色一致，最後 5 秒可轉為強調色   |
| 音效 | 可有結束音，但不要每秒滴答聲       |
| 位置 | 優先右上角；Slide 2 可放下方中央 |
| 操作 | 能由講師點擊後開始，或進入頁面自動開始  |

---

# 4D 導覽列規格

從 Slide 5 開始，每頁都建議放 4D 導覽列。

格式：

```text
Discover 探索 → Define 定義 → Develop 發展 → Deliver 交付
```

## 呈現方式

|      頁數 | 高亮階段            |
| ------: | --------------- |
| Slide 5 | Discover 探索     |
| Slide 6 | Define 定義       |
| Slide 7 | Develop 發展      |
| Slide 8 | Deliver 交付      |
| Slide 9 | 四個階段全部呈現，不需單一高亮 |

## 視覺要求

* 放在頁面上方或下方固定位置。
* 當頁階段用主色或加粗高亮。
* 其他階段用灰色。
* 不要搶走主內容焦點。

---

# 動畫整體原則

這份簡報的動畫要幫助帶活動，不是裝飾。

| 原則     | 說明                         |
| ------ | -------------------------- |
| 逐步揭露   | 特別是 Slide 4 的限制條件，必須一條一條出現 |
| 避免複雜轉場 | 不要飛入、旋轉、彈跳過多               |
| 保持節奏   | 每頁動畫不超過 3–5 個動作            |
| 支援講師停頓 | 重要反轉要讓講師可以先講，再點出文字         |
| 可控     | 盡量用點擊觸發，不要全部自動跑完           |

---

# 給設計師的特別提醒

## 1. Slide 4 是活動的關鍵反轉頁

這頁不能一開始把所有條件都露出來。
要讓講師先問學生第一輪答案，再逐條揭露限制，產生落差感。

---

## 2. Slide 9 是學生最可能拍照的頁面

這頁要像一張完整的學習海報：

> Discover 探索 → Define 定義 → Develop 發展 → Deliver 交付
> 發散 → 收斂 → 發散 → 收斂

請確保：

* 字夠大
* 圖夠清楚
* 中英對照不擁擠
* 遠距離也看得懂

---

## 3. 不要把講師口語稿全部放上投影片

投影片只放活動指令與關鍵概念。
細節由講師現場說。

---

# 最後可附給設計師的簡短摘要

這份簡報是一個 10 分鐘設計思考體驗活動。
整體要做成**清爽、現代、工作坊感**，文字以英文為主、繁中為輔。前半段透過「我肚子餓」製造直覺解方與真實限制的落差；後半段對應到官方四階段：**Discover 探索、Define 定義、Develop 發展、Deliver 交付**。最後一頁用雙鑽石的發散收斂圖收斂學習重點。
